## 1. 概要

### 1.1 目的
中小病院向けに、標準仕様（基本要件）に**準拠**したクラウド・ネイティブ型レセプトコンピュータ（以下「本システム」）を開発する。本システムは以下を実現する。

1. 診療行為等の情報に基づく診療報酬の算定・患者負担金の計算
2. 診療報酬明細書（レセプト）の作成および請求処理
3. 共通算定モジュールとの連携による診療報酬改定対応コストの極小化
4. 医療DXサービス群（オンライン資格確認等システム、電子処方箋管理サービス、電子カルテ情報共有サービス等）との接続
5. 価格公開・データ移行規格の標準化によるマーケット透明性への貢献

### 1.2 適用範囲
- 対象：中小病院（歯科を除く医療機関）向けレセコン。中小病院以外の医療機関への導入も妨げない
- 電子カルテとの一体型／分離型のいずれの形態も対象とする。一体型の場合、同一事項について第1章（電子カルテ標準仕様書）の規定と本章の規定が異なるときは**第1章を優先**する
- 本標準仕様に規定される項目と関連のない独自機能の実装は制限しない

### 1.3 要件の分類
標準仕様の類型に従い、各要件に以下の区分を付す。

| 区分 | 意味 | 対応 |
|---|---|---|
| 【遵守】 | 標準仕様準拠のため実装・対応必須 | 必須 |
| 【推奨】 | 実装・対応が推奨（将来「遵守」化の可能性あり） | 任意（実装を強く推奨） |
| 【参考】 | 検討中事項・参考情報 | 任意 |

## 3. 機能要件

### 3.1 基本業務機能
標準仕様はレセコンを「診療行為等の情報に基づき診療報酬を算定し、患者負担金を計算するとともに、レセプトの作成及び請求処理を行う機能を有するコンピュータ」と定義する。これを踏まえ、以下を本システムの基本機能とする。

- FR-01 患者・保険情報管理（患者基本情報、保険資格情報の登録・管理）
- FR-02 診療行為情報の取込・入力（電子カルテ連携または手入力）
- FR-03 診療報酬の算定（共通算定モジュール連携による。3.2参照）
- FR-04 患者負担金の計算・会計処理
- FR-05 レセプト（診療報酬明細書）の作成（「電子レセプトの作成手引き」記録方式に準拠）
- FR-06 レセプト請求処理（オンライン請求対応）
- FR-07 返戻・再請求管理
- FR-08 各種帳票出力・統計

※個々の医療機関において業務上不要な機能まで実装導入を強制するものではない（標準仕様2.1.1の注記に同じ）。

## 4. 非機能要件

### 4.1 可用性【遵守】

| ID | 要件 |
|---|---|
| NFR-01 | 稼働率実績が原則として**99.9%以上**であること（稼働率＝年間実稼働時間／年間予定稼働時間×100）。新規製品は目標稼働率99.9%以上を要件とする。稼働率はサービス仕様書等で定義された責任分界の範囲内で算出し、クラウドプロバイダー障害による停止時間は算出対象外として差し支えない |
| NFR-02 | 稼働率が99.9%未満となった場合、直ちに障害の内容・原因・対策を整理し、再発防止策を構築・実施できる体制を準備すること |
| NFR-03 | 運用時間は24時間365日とする（接続回線の計画停止、大規模災害、連携サービス障害、自システムの計画停止、医療機関側の停電・機器故障等の自責によらない停止を除く）※別紙2 A.1.1.1 |

## 5. アーキテクチャ要件

### 5.1 必須【遵守】

| ID | 要件 |
|---|---|
| AR-01 | レセコンを構成するアプリケーションは、原則として**パブリッククラウド環境で稼働**すること。ただし以下の機能を有するアプリケーションは例外とする：①医療機関内設置機器（資格確認端末、プリンター等）との通信中継・制御 ②見読性担保のためのデータ保管 ③クラウド障害等の非常時における事業継続 |
| AR-02 | **モダン化された技術**を採用すること（マネージドサービスの利用、疎結合なアーキテクチャの採用、多要素認証の導入等） |

### 5.2 推奨【推奨】

| ID | 要件 |
|---|---|
| AR-11 | クラウド上で稼働する全アプリケーションが**SaaS型**であること |
| AR-12 | **マルチテナント方式**であること（GCASガイド「アーキテクチャ要件を満たすシステム構成」に準拠） |
| AR-13 | ソースコードは全テナント共通を前提としたサービス設計とし、テスト・更新等による一時的なものを除き複数バージョンが併存しない仕様であること（診療科特化のためのソースコード区分は、管理体系が明確な場合に限り併存に当たらない） |
| AR-14 | 個々の医療機関におけるカスタマイズに対応不可能な仕様とすること。ただし全医療機関が利用可能なオプション機能（管理画面での有効化・無効化、利用範囲選択等）はカスタマイズに当たらない。設定・メタデータ変更による環境対応は差し支えない |

### 6.3 外部システム等間の連携共通仕様・部門システムAPI
- 標準仕様上は「次版以降において設定予定」。本システムでは将来の遵守化に備え、第1章別紙5「連携共通仕様（イメージ）」の設計方針（下表）との整合を保った設計とすることを推奨する。

| 項目 | 方針 |
|---|---|
| 通信プロトコル | HTTPS（TLS1.2以上、1.3推奨）。インターネット経由はmTLSまたはIPsec等で接続拠点限定 |
| アーキテクチャ | REST API（リソース指向）。超高頻度ストリーミング等は限定的にWebSocket/gRPC等を許容 |
| データ規格 | HL7 FHIR R4／JP Core／JP-CLINS準拠、JSON（application/fhir+json）、UTF-8 |
| 認証・認可 | OAuth 2.1 クライアント・クレデンシャル・フロー（秘密鍵署名JWT）。アクセストークン有効期限15分〜1時間 |
| バージョニング | URLパス方式（/v1/）。後方互換性維持を原則、破壊的変更はメジャーバージョン更新＋並行稼働期間 |
| エラー処理 | HTTPステータスコード＋OperationOutcomeリソース返却。X-Request-IDによる追跡・監査ログ記録 |

## 7. データ移行要件

- レセコン間データ移行の標準仕様（遵守・推奨）は**次版以降に設定予定**。現時点の設計指針として以下を織り込む。
  - DM-01 移行対象項目は「レセプト電算処理システム 電子レセプトの作成手引き」記載項目を前提とする
  - DM-02 電子カルテ—レセコン連携仕様（今後策定）およびに共通算定モジュール仕様との整合を図る
  - DM-03 医療機関等の要請があった場合にデータ移行に必要な事項（データ形式を含む）を開示できるよう、移行用エクスポート機能とその仕様文書を整備する（8.の情報公開要件と連動）

## 9. 留意事項・今後の改定対応

1. **第1章との優先関係**：電子カルテ一体型システムでは、同一事項について規定が異なる場合、第1章（電子カルテ標準仕様書）の規定を優先適用する
2. **定期改定への追随**：標準仕様は定期改定が予定されており、以下が追加見込み。改定内容を継続的にウォッチし対応計画を立てること
   - 接続対象サービスの拡大（共通算定モジュールの請求支援機能、診療報酬改定対応、医療保険法等改正対応、国公費負担医療・地方自治体医療費助成の現物給付化対応、予防接種のデジタル化）
   - 標準コード・マスタの策定反映
   - レセコン—外部システム等間の連携仕様、データ移行仕様の追加
   - 3省2ガイドライン改定に伴うセキュリティ要件の追加
3. **経過措置の管理**：電子処方箋・電子カルテ情報共有サービスに係る遵守要件は、クラウド間連携実現公表から6か月の経過措置があるため、公表動向を監視し適用時期を管理すること
